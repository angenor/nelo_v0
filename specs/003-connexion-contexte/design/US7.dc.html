T1a · US7 · changer de numéro de téléphone

Le code part vers le nouveau numéro, l’identifiant ne change qu’après, et l’ancien numéro est prévenu

Depuis son espace, le changement suit les règles du code reçu (dix minutes, cinq essais, soixante secondes) et la session survit. Quand la carte SIM est perdue, le secrétariat change le numéro : toutes les sessions tombent, les appareils sont oubliés, et la première ouverture par code reçu tient lieu de vérification.

Depuis son espace

Pages dans la coquille, contexte tactile standard (48 px). Le numéro actuel s’affiche dans le détail de son propre compte.

ÉCART
Le refus « déjà utilisé » n’est pas prévisible avant l’envoi
AUT_IDENTIFIANT_DEJA_UTILISE arrive en 422 après l’envoi ; ni /moi/telephone ni /comptes n’ont de pendant /verification (03-api § 3, règle 3). L’écran l’annonce donc au retour du serveur, dans le champ. Soit le contrat gagne un pendant, soit la spec accepte l’annonce après le premier envoi.
ÉCART
Le libre-service dévoile qu’un numéro est pris
Dire à une personne connectée que le numéro qu’elle saisit appartient à un autre compte publie une information que /auth/otp refuse de publier (FR-004). La spec le veut (FR-036) ; l’écart entre les deux routes mérite une ligne dans les hypothèses.
QUESTION OUVERTE
L’écran « Mon compte » n’existe pas encore
Le profil (/moi/profil) arrive avec T3a. La page compte/telephone.vue de R-21 a besoin d’un point d’entrée dans la coquille : lequel, tant qu’il n’y a pas de profil ? Le menu de l’avatar est le candidat naturel, et il n’est pas dessiné.
